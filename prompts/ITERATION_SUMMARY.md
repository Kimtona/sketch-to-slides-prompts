## 보고서 Iteration Process에 쓸 수 있는 흐름

1. **구현 → 현실과의 차이:** 초기 구현을 마친 뒤 실제 모델을 붙이자(P01) 좌표 드리프트·반복 출력·LaTeX 오염이 드러났고, 각각 단위 테스트가 가능한 보정(재배율, salvage, 이스케이프 복구)으로 해결.
2. **측정 기반 개선:** "느리다"를 토큰 수/속도(1,481토큰 ≈ 215–245초)로 분해하고, 출력 형식을 바꿔(JSON+좌표 → Markdown 176토큰) 35초로 줄임(P20→P21). 같은 이미지 반복 시 프롬프트 캐시 효과는 별도 표기.
3. **자동 테스트가 놓친 것을 실제 사용으로 발견:** 복합 스크린샷의 표·리스트 실패(P19–P20), 변환 수식의 첫 클릭 문제(P22). 두 번 모두 "원인부터 → 재현하는 실패 테스트 → 최소 수정" 순서로 처리했고, 실제 모델 출력을 fixture로 저장해 재현 가능하게 함(`tests/fixtures/sketch/`).
4. **정직한 보고 요구:** 실패·미달성은 그대로 보고(60초 미달성 → Document Mode 승인 후에만 달성, 7B가 굵게/기울임 인식 못함, Layout 모드의 인용문 미인식).
5. **협업·안전 장치:** 동시 세션 충돌 방지(P05–P06), 승인 후에만 병합·push·tag·게시(P17, P26–P30), 강제 push 금지.
